# Infrastructure Parity with KMMTemplate

**Goal:** Bring the project's tooling, CI, gradle infrastructure and AI-development context up to the level of `~/StudioProjects/KMMTemplate`, without touching feature code or migrating frameworks (no Koin / MVIKotlin / moko / multi-module / library upgrades in this PR).

**Architecture:** Infrastructure-only changes that surround the existing single-module `composeApp`. We introduce a `build-logic` composite build with reusable utilities, wire Detekt + Android Lint at the root level, ship git hooks and GitHub Actions workflows, add lint configurations for both Kotlin and Swift, and seed the AI-agent infrastructure (`CLAUDE.md`, `.claude/rules`). The app code, its DI (`InjectProvider`), its custom `BaseViewModel`, its resources (`composeResources/strings.xml`) and its package layout remain untouched.

**Tech stack (unchanged):** Kotlin 2.0.0, Compose Multiplatform 1.6.11, AGP 8.3.0, Apollo 4.0.0-beta.6, Supabase 2.5.0, Coil 3.0.0-alpha06, kotlinx.coroutines 1.9.0-RC, kotlinx.serialization 1.7.0. New tooling additions only.

**Out of scope (future PRs):** version upgrades, Koin migration, MVIKotlin migration, multi-module split, moko-resources adoption, signing/release workflow, KMP Module Generator templates.
